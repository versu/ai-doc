# PR 本文の雛形

読み手は PR を作るエージェント。文章の基準は [pr-writing.md](pr-writing.md) を参照。

```markdown
# <タイトル。何が変わるかを1行で。ドメイン用語で>

## 目的
（なぜこの変更が必要か。Scope lock の「目的」をドメイン用語で言い換える）

## やったこと
（1〜数行。実装の1行サマリをもとに、レビュアーに伝わる粒度で）

## 受け入れ条件
- [ ] （spec の受け入れ条件。満たしたものにチェックを入れる）

## 確認のしかた
（レビュアーが動かして確かめる手順。画面があれば操作の流れ）

## 関連
Closes #<この変更に対応する Issue の番号>

## 先送り
（今回直さなかったものと、その理由。無ければ節ごと省く）

## 依存
（**宛先が既定ブランチでない場合のみ**）
この PR は #<先行する PR の番号> の上に積んでいる。マージは #<先行> → この PR の順。
```

## 節の省き方

- 「先送り」が無ければ節ごと省く。空の節はノイズになる
- 「依存」は宛先が既定ブランチのときは書かない
- 「確認のしかた」は、自動テストだけで確認できる変更ならその旨を1行で書く
