# Notion への書き込み

## 目的

用意済みの内容を、指定された Notion のページかデータベースに書き込む。
**書く内容はこのスキルでは作らない。** 文章の作成・推敲は呼び出し前に済ませておき、このスキルは Notion への反映だけに注力する。
同じ理由で、書き込む前のプレビュー（内容の確認）は行わない。内容の合意は、内容を作った側で済んでいる前提とする。

## 渡されるもの

起動時の指定を優先し、**指定が無い項目だけ** `AskUserQuestion` で確認する。

| 項目 | 指定の例 | 指定が無いとき |
|---|---|---|
| 内容 | Markdown ファイルのパス、または会話中の文章 | どれを書き込むのか確認する |
| 書き込み先 | ページの URL・ページ名、またはデータベースの URL・データベース名 | 書き込み先を確認する |
| 書き込み方 | 新規作成 / 追記 | 確認する（書き込み先がデータベースなら新規作成に決まるので聞かない） |
| ワークスペース | `private`、`work` など（Notion の MCP サーバー名かその一部） | Notion の MCP サーバーが1つならそれを使う。複数あれば確認する |
| タイトル | 新規作成するページのタイトル | 内容の先頭の `# ` 見出しを使う。無ければ確認する |
| プロパティ | データベースに作るページのプロパティ（例: ステータス=Doing） | 手順5で確認する |

書き込み先と書き込み方の組み合わせで、することが決まる。

| 書き込み先 | 書き込み方 | すること |
|---|---|---|
| ページ | 新規作成 | そのページの子ページとして作る |
| ページ | 追記 | そのページの末尾に追記する |
| データベース | 新規作成 | そのデータベースにページを作り、プロパティを設定する |
| データベース | 追記 | 成り立たないので止まる（追記先のページを指定し直してもらう） |

## 単体での起動例

```text
/write-notion-page .ai/_tasks/foo/knowledge.md を private の tasks データベースに新規作成して。ステータスは Done
/write-notion-page この会話でまとめた手順を https://app.notion.com/p/xxxx に追記して
```

## 手順

**下の「停止条件」に当たったら、書き込まずに理由を報告して止まる。**

### 1. ワークスペース（MCP サーバー）を決める

利用可能なツールの一覧から、`notion-fetch` を持つ MCP サーバー（`mcp__<サーバー名>__notion-fetch`）を列挙する。

- 指定があれば、名前が一致する（または指定を含む）サーバーを使う
- 指定が無く、サーバーが1つならそれを使う。複数あれば `AskUserQuestion` でどれに書くか選んでもらう

以降の Notion のツールは、すべてこのサーバーのものを使う。ツールが遅延読み込みになっていれば、先に ToolSearch でスキーマを読み込む。

### 2. 内容を読み込む

- ファイルが指定されたら、**ファイルの現在の内容**を読む（会話中に表示された古い内容を使い回さない）
- 新規作成でタイトルを先頭の `# ` 見出しから取った場合は、本文からその見出しを取り除く（Notion ではタイトルがページの上に表示されるため、本文に残すと二重になる）

### 3. 書き込み先を特定する

- URL が指定されたら、`notion-fetch` で取得する
- 名前が指定されたら、`notion-search` で探す。候補が複数あれば、パス（親ページ）を添えて `AskUserQuestion` で選んでもらう。1件も無ければ止まる
- 取得した結果で、ページかデータベースかを判断する。指定された書き込み方と合わない組み合わせ（データベースへの追記）なら止まる
- データベースが複数のデータソースを持つときは、どのデータソースに作るか確認する

### 4. 画像をアップロードする

内容の中の画像（`![代替テキスト](パス)`）を、パスの種類で扱い分ける。

| パス | 扱い |
|---|---|
| ローカルのファイル | Notion にアップロードして、参照を差し替える |
| `https://` の URL | そのまま残す（Notion が外部の画像として表示する） |

相対パスは、**内容のファイルがあるディレクトリ**を起点に解決する（作業ディレクトリ起点ではない）。

ローカルの画像1つにつき、次を行う。

1. `notion-create-file-upload` を `filename`（ファイル名）だけ指定して呼ぶ。`content_type` は拡張子から推定させるため省略する
2. 返ってきた `upload_url` に、`upload_headers` のヘッダーをすべて付けて POST する

   ```bash
   curl -sS -X POST "<upload_url>" -H "<ヘッダー名>: <値>" -F "file=@<画像の絶対パス>"
   ```

3. 返ってきた `markdown_source`（または `suggested_markdown`）で、内容の中の画像の参照を差し替える

1ファイルの上限は 20 MiB。アップロードした画像はページに置かないと期限切れで消えるので、**手順6まで続けて進める**。

### 5. プロパティを決める（データベースに作るときだけ）

`notion-fetch` でデータソース（`collection://...`）を取得し、プロパティの名前・型・選択肢を確認する。

- 指定されたプロパティを、取得したスキーマの名前と選択肢に合わせる。名前や選択肢が一致しなければ、近いものを示して確認する
- タイトルのプロパティには、手順2で決めたタイトルを入れる
- 指定されていないプロパティは、`AskUserQuestion` で設定するかどうか確認する。選択肢があるプロパティは、その選択肢を示して選んでもらう。値を入れないことも選べるようにする
- 日付などの書式は、`notion-create-pages` の説明にある形式に従う

### 6. 書き込む

書き込む前に、`notion://docs/notion-flavored-markdown-spec` を `notion-fetch` で読み、内容を Notion の Markdown に合わせる（独自の記法を推測で書かない）。

| すること | 使うツール |
|---|---|
| 子ページを作る | `notion-create-pages`（parent は書き込み先のページ。`properties` は `title` だけ） |
| データベースにページを作る | `notion-create-pages`（parent は手順3・5で確認したデータソースの `data_source_id`） |
| 末尾に追記する | `notion-update-page`（`command: "insert_content"`、`position: {"type": "end"}`） |

非同期で受け付けられた（`async_task` が返った）ときは、`notion-get-async-task` で完了を待ってから報告する。

## 停止条件

| 条件 | 理由 |
|---|---|
| Notion の MCP サーバーが1つも無い | 書き込めないため |
| 内容のファイルが無い・空 | 書くものが無いため |
| 書き込み先が見つからない、またはアクセスできない | 別の場所に書くと、ユーザーが見つけられないため。ワークスペースの指定違いも疑って伝える |
| 書き込み先がデータベースで、書き込み方が追記 | データベースには追記できないため。追記先のページを指定し直してもらう |
| ローカルの画像が見つからない、またはアップロードに失敗した | 画像が欠けたページができるため。どの画像かを示し、画像を外して書くか直してから呼び直すかを確認する |

## 返すもの

- 書き込んだページの URL
- したこと（子ページの作成 / データベースへの作成 / 追記）と、ワークスペース
- データベースに作った場合は、設定したプロパティ
- アップロードした画像の数
- ツールの結果に `warnings` があれば、その内容
