# エラーハンドリングガイドライン

特定のプログラミング言語に依存しない、基本的なエラーハンドリングの方針をまとめる。
エラーを「回復可能」「回復不可能」で分類し、それぞれで**伝達手段**と**呼び出し側の対処**を
どう決めるかを整理する。

---

## 1. エラーを呼び出し元に伝える手段

エラーを呼び出し元へ伝える手段は、次の 2 つを使い分ける。

- **例外（Exception）**: 呼び出し階層を遡って伝播させる。
- **エラークラス（Result 型）**: メソッドの戻り値でエラーを表現する。具体的には、エラー種別と
  メッセージを含むクラスを返す。
  - エラー種別は**判別可能**であること。呼び出し側が種別ごとに分岐して対処を変えられる形にする。

---

## 2. エラー種別と対応方針の整理

エラーは「回復可能かどうか」で分類し、伝達手段を決める。

- **回復可能**
  - 概要
    - 利用法上の問題（利用者側が正しい使い方をしていれば回避できる）。
    - 事前条件・不変条件からの逸脱。
  - 対応方針
    - **エラークラス（Result 型）で表現する**。
- **回復不可能**
  - 概要
    - 対処のしようがない致命的な問題。
      - 物理障害・環境構成ミス等によるアプリケーション実行停止。
        - 例: 通信エラーの発生、接続先サーバーが見つからない。
      - プログラムコードの論理バグ、あるいは永続化データの不整合検知による実行停止。
        - 例: Null 参照、数値変換の失敗。
  - 対応方針
    - **例外で表現する**。

---

## 3. エラー種別ごとのハンドリング方針

エラーが発生した処理（メソッド）の呼び出し側が、どのように対処するか。

- **回復可能**
  - 返す側は、回復可能な形（エラークラス）でエラーを返す。
  - 受け取った側（各ユースケース等）が、**その文脈で回復するか／上位へ委ねるかを判断する**。
    - 同じエラーでも、呼び出し文脈によって回復できるかどうかは変わりうる。回復できない文脈では
      上位へ委譲する。
- **回復不可能**
  - 呼び出し側では catch せず、**最上位層で共通処理（ログ記録・レスポンス整形）を行う**。

```text
# ✅ 良い例（回復可能: 呼び出し側でエラー種別ごとに分岐して対処する）
result = usecase.execute(input)
if (result.isFailure) {
    switch (result.error.type) {
        case NotFound:      return notFoundResponse(result.error.message)
        case AlreadyDone:   return conflictResponse(result.error.message)
    }
}
return okResponse(result.value)

# ❌ 悪い例（回復不可能: 途中層で例外を握りつぶし、原因を隠してしまう）
function process(order) {
    try {
        return repository.save(order)   # 通信エラー等は回復しようがない
    } catch (e) {
        return null                     # 握りつぶすと最上位でのログ・整形もできない
    }
}

# ✅ 良い例（回復不可能: 途中層では catch せず、最上位層まで伝播させる）
function process(order) {
    return repository.save(order)        # 回復不可能な例外はそのまま伝播させる
}
```

---

## 4. ログレベルの指針

エラーを記録する際は、エラー種別に応じてログレベルを使い分ける。

- **回復可能（業務エラー）**: 記録する場合は **Warning** で出力する。
  - 利用法上の問題・事前/不変条件からの逸脱など、運用上は把握したいが致命的ではないもの。
  - 例: 取り込み対象が0件（すべて登録済み・対象外）だった等の業務上の分岐。
- **回復不可能**: 最上位層で **Error** として記録する。
  - 障害・環境構成ミス・論理バグ・データ不整合など、対処が必要な致命的問題。

---

## 5. 方針まとめ

| エラー種別 | 概要 | 伝達手段 | 呼び出し側の対処 | ログレベル |
|---|---|---|---|---|
| 回復可能 | 利用法上の問題・事前/不変条件からの逸脱 | エラークラス（Result 型） | 文脈に応じて回復、または上位へ委譲する | Warning |
| 回復不可能 | 致命的な問題（障害・環境構成ミス・論理バグ・データ不整合） | 例外 | catch せず、最上位層で共通処理（ログ記録・レスポンス整形） | Error |
