
# Gitコミットメッセージの書式ルール

このルールは、すべてのコミットに対して適用されるコミットメッセージのガイドラインです。
以下のルールに則り、日本語でGitコミットメッセージを記述してください

## 基本フォーマット（必須）

```
<Prefix>: <日本語サマリ（命令形/簡潔に）>

==== Why ====
なぜ変更したかがわかる内容を記載する (whatではなく、whyを記す)

==== What ====
何を行ったかの概要を箇条書きで示す

Refs: #<Issue番号>（任意）
```

## Prefix（先頭プレフィックス）
- feat: 新機能の追加
- fix: バグ修正
- refactor: リファクタリング（挙動変更なし）
- test: テスト追加/修正
- docs: ドキュメント更新
- chore: 雑務（ツール設定/スクリプト等）
- revert: 取り消し

## サマリ（1行目）
- 日本語で簡潔に。末尾の句点は不要。
- 何を・なぜ（必要なら）を短く表現。
- 文字数はおおよそ50文字以内を目安に。

## 本文（背景）
- なぜ変更したかがわかる内容を記載する (whatではなく、whyを記す)
  - 何をしたか（what）は変更内容を見ればわかるので、変更の背景（why）を記載する
- 原則として日本語。必要に応じて技術用語は英単語可。

## 本文
- 修正内容を箇条書きで簡潔に示す。細かい修正内容は不要で概要レベルでOK

## フッター（任意）
- BREAKING CHANGE: 後方互換を壊す変更がある場合は内容を明示。

## 例

```
feat: ユーザー取得APIを実装

==== Why ====
ユーザー情報を参照する機能において、クライアントからユーザー情報を取得する手段が必要となったため。

==== What ====
- ユーザー取得APIエンドポイントを追加
- テストを追加
- エンドポイントを元にopenapi-spec、api-clientを生成

Refs: #123
```

## 禁止事項
- 英語だけのサマリ（原則日本語で記述）
- 曖昧なサマリ（例: "update", "fix bug" 等）
