# .NET 機能テスト(FeatureTest)実装ガイドライン

本プロジェクト(.NET / ASP.NET Core + EF Core)における機能テスト(= 結合テスト / IntegrationTest)の実装方針。

- 言語非依存の基本方針(確認内容・命名・AAA)は `@.ai/docs/feature-test-guide.md` を参照。本ファイルは .NET 固有・構成固有の事項のみを定める。
- 同一構成の他プロジェクトでも再利用する前提で、特定の機能名・エンティティ名・エンドポイントに依存しない汎用ルールとして記述する。

---

## 1. ディレクトリ構成と責務の分離

```
Fixtures/                 ... 複数クラス間で共有したい処理・基盤の置き場所
  Factories/              ... 複数クラス間で共有したい Entity の Factory の置き場所
    Common/               ... Factory 間で共有する汎用ユーティリティ（デフォルト値適用など）
BackgroundJob/            ... Goof.PsBee.BackgroundJob のFeatureTest
  {BackgroundJobName}/
    {BackgroundJobName}Test.cs    ... 個別機能のテスト
```

- **個別テストケースの Arrange 処理を共有 Factory に置かない。**
- **1つのテストケースだけが必要とする Entity 生成を共有 Factory に置かない。**
- 共有 Factory に置くのは、複数クラスで再利用される **Entity の Factory**(必須項目のみセットする Factory／任意項目も含め全てセットする Factory 等)。
- 共有の DB 操作ヘルパー(`SeedAsync` 等)は `TestUtils` のような共有ユーティリティにまとめる。

---

## 2. Factory の実装方針

### 2.1 各プロパティの値の決め方

- Factory は対象 Entity の**全プロパティを引数で受け取れる**ようにし、呼び出し側が任意の値を注入できるようにする。未指定の項目は Factory が既定値で埋める。
- 自由入力でよい項目は、**Bogus の `Faker` でランダム値**を入れる。
- 値が特定の有効集合・形式に制約される項目(列挙の名称解決など)は、**有効な値の中からランダムに選ぶ**。無効な文字列を入れない。

### 2.2 デフォルト値と空値の扱い

- 基本は「**外から渡す値が空ならデフォルト値をセットする**」設計とする。
- ただし、**意図的に空値をセットしたいケース**にも対応する。
  - `useDefaultValueIfEmpty`(bool, 既定 `true`)のようなフラグを用意する。
    - `true`(既定): 外から渡す値が空ならデフォルト値を使う。
    - `false`: 外から渡す値が空でもデフォルト値を使わない(= 渡された空値をそのまま使う)。
  - このフラグは**オプショナル項目にのみ**適用する。**必須項目には適用しない**(必須項目を空で DB 保存できないため)。

### 2.3 関連エンティティの生成

- Factory で関連エンティティを**勝手に生成しない**(すぐに破綻するため)。
  - 例: 子を作るときに親も作る、のような連鎖生成はしない。
- 関連エンティティを生成してよいのは、**明確な親子関係(= 集約単位)**の場合のみ。
- それ以外は、**呼び出し側が依存関係を理解した上で、適切な順序で各 Factory を呼ぶ**設計にする。

### 2.4 共通ロジックの切り出し

- 複数 Factory で共通して使う処理(デフォルト値適用 `useDefaultValueIfEmpty` の判定など)は、各 Factory に重複実装せず、`Factories/Common/` 配下の共通ユーティリティに切り出して再利用する。

## 3. テストケース(メソッド)の書き方

- **テストケース内で完結させる**。そのテストが何を検証しているかをメソッド本文だけで把握できるよう、多少冗長でも Arrange〜Assert を本文に書く。テスト固有のオーケストレーション(前提データの組み立て・操作・期待値)を private ヘルパーや共通処理に切り出して**共通化しない**。
- **Entity は共有 Factory で生成し、テストに意味のある値だけを明示的に渡す**。シナリオを決める値だけをテストケース側で指定し、検証に無関係な項目は Factory のデフォルトに任せる。
- **メソッド呼び出しは名前付きパラメータを使う**。Factory・ドメインメソッド等の呼び出しで、各引数が何を表すかを呼び出し箇所で読み取れるようにする。
