# commit Skill

今回の作業で行った修正をコミットするワークフロー。

## 参照
- コミットメッセージ規約: `.ai/docs/git-commit-comment-rule.md`

## ワークフロー

### 1. 今回の修正をステージする
- `git status` / `git diff` で変更内容を確認する。
- **今回の作業でClaudeが作成・編集したファイルのみ** を `git add <path...>` でステージする。
- セッション開始時から存在する無関係な未ステージ変更は **ステージしない**（巻き込まない）。
  判断に迷う変更があればユーザーに確認する。

### 2. コミットメッセージを作成する
`.ai/docs/git-commit-comment-rule.md`（毎回その時点の最新内容を参照）に従い、日本語で作成する。
- Prefix・サマリ・本文の構成や見出しはすべて規約ファイルに従う。
  （書式の詳細はこのスキルに複製しない＝規約変更に追従させるため）

### 3. ステージ済みの状態でメッセージを提示し、承認を求める
- **メッセージ案を提示する前に、手順1のステージを必ず完了しておく**
  （ユーザーがステージ内容を見たうえで判断できるようにするため）。
- ステージ結果（`git status`）とコミットメッセージ案を併せて提示し、`AskUserQuestion`toolでコミットしてよいか確認する。
- 修正要望があれば反映してから次へ進む。

### 4. コミットする
承認されたら、ステージ済みの内容に対して `git commit` を実行する。
- 本文込みでメッセージを渡す（`-m` を複数指定、または heredoc）。
- 署名や Co-authored-by 等の付加情報は付けない（規約どおりのメッセージのみ）。
- push は行わない（明示の指示があった場合のみ）。
