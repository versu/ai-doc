# スキル作成ガイドライン

本リポジトリのプラグイン（`plugins/<プラグイン名>/`）にスキル・エージェントを追加するときの方針をまとめる。

## 配置

| 種類 | 置き場所 |
|---|---|
| スキル | `plugins/<プラグイン名>/skills/<スキル名>/SKILL.md` |
| エージェント | `plugins/<プラグイン名>/agents/<エージェント名>.md` |
| スキル横断で使うガイド | `plugins/<プラグイン名>/_docs/` |
| そのスキルでしか使わない補助ドキュメント | `plugins/<プラグイン名>/skills/<スキル名>/references/` |

エージェントは `agents/` の直下に置き、サブディレクトリで分類しない。
プラグインとして読み込まれた場合、サブディレクトリ名が呼び出し名の一部になり（`core:review:security` のようになり）、ローカルでの名前と食い違うため。

## ドキュメントの参照

SKILL.md では `@` によるインポートが使える。相対パスは**作業ディレクトリ基準**で解決されるため、どのプロジェクトから読まれても解決できるよう `${CLAUDE_SKILL_DIR}`（SKILL.md があるディレクトリに置き換わる）を起点に書く。

```markdown
@${CLAUDE_SKILL_DIR}/../../_docs/git-commit-comment.md
```

スキル自身の `references/` を参照するときは、相対リンクでよい。

```markdown
詳細は [references/xxx.md](references/xxx.md) を参照する。
```

## 他のスキル・エージェントを呼び出すスキル

呼び出し名は、読み込まれ方によって変わる。

| 読み込まれ方 | 名前 |
|---|---|
| プラグイン経由（導入先プロジェクト） | `core:implementation-review` |
| ローカル（本リポジトリでの開発中） | `implementation-review` |

どちらでも動くよう、**呼び出し先の名前は SKILL.md の冒頭に表で1回だけ書き**、本文では役割名で参照する。

```markdown
## 呼び出し先

利用可能なスキル・エージェントの一覧を確認し、左の名前があれば左を、なければ右を使う。

| 役割 | 種別 | プラグイン経由の名前 | ローカルの名前 |
|---|---|---|---|
| 実装レビュー | エージェント | `core:implementation-review` | `implementation-review` |
| コミット | スキル | `core:commit` | `commit` |

## 手順

1. 「実装レビュー」エージェントを起動する（名前は上の表で解決する）。
```

呼び出して失敗したら次を試す、という書き方にはしない。失敗した呼び出しの分だけ時間とトークンを消費するため、**呼び出す前に一覧を確認して選ぶ**。

## description の書き方

`description` はスキルが使われるかどうかを決める唯一の手がかりになる。何をするかに加えて、**どういうときに使うか**を具体的に書く。

- ユーザーが実際に打ちそうな言い回しを含める（「コミットして」「変更をコミットして」等）
- 対象外の領域があれば明示する
- 近い領域のスキルがあるときは、どちらを使うかの棲み分けを書く
